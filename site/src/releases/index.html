What is still needed

  • Pinned runtime and release. Real immutable artifacts and digests, source identity, compatibility checks, matching installer instructions and a supported-host matrix.
  • Extension and agent guides. Delivered discovery, scaffold, check, preview and maintenance instructions verified against that exact release.
  • Release qualification. Clean Linux and physical Pi evidence, core operation without agents, fresh-agent and cross-agent maintenance, upgrade preservation and clean-host restore.
  • Companion acceptance. Physical-device behavior, pairing and restore checks, final privacy wording and an available companion distribution channel.
  • Hosting. An operator-selected hostname, actual site artifact and verified hosting privacy details. Public hosting is not selected.

Future release links must be immutable

A release page must bind each installer, runtime, guide and compatibility manifest to actual verified versions and digests. It must not run scripts from a moving branch. When those inputs exist, a separately reviewed change can add matching versioned guides and an installation prompt.

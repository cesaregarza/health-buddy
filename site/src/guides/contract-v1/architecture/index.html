Contract v1 guide · pre-release

One workspace, clear ownership.

The interface should stay understandable to you and to the next agent that works on it.

The planned data path

  1. Dashboard, CLI, tools and extensionsPresent information and request scoped operations.
  2. Canonical operationsApply authentication, bounds, identity, revisions, retry handling and atomic writes.
  3. Authoritative store adaptersPreserve manual CSV/JSON and HealthKit SQLite formats and provenance.

Views, agents and connectors must not bypass operations to write store files. Generated reports and caches are rebuildable outputs, not another source of truth. Crash recovery must settle partial transactions before reads resume; that needs implementation evidence.

Three identities to keep separate

Code release
The exact source and immutable runtime artifacts you run. Contract version 1.0.0 is not a product release.
Dataset and revision
The authoritative stores and personal workspace, with a revision for accepted canonical changes.
Installation and restore epoch
The receiver identity and security epoch. A restore creates a fresh epoch; old credentials and prepared operations must not become valid again.

Ownership extends beyond rows

A persistent personal tree holds extension source, assets, configuration, tests, notes, migration history and state independently of the runtime. The operation journal, retry ledger and identity metadata are also authoritative backup inputs. Caches can be omitted only when rebuilding is verified.

Separate health access from code maintenance

An agent health grant permits only approved record operations. It does not authorize code installation, extension activation or device management. Native Codex or Claude Code maintenance uses a separate owner-authorized boundary. Native extensions are trusted code with the risks of their operating-system privileges.

A phone grant is scoped to its bound ingestion and sync status. Tailscale transport and application authorization are separate. Neither an opaque ID nor a claimed proxy header proves authority.

This website is outside the health data path

The public static site is informational. The installed product is required to operate without it and ship matching docs for local access. No health data, pairing secret or device identity belongs in a public page or URL.

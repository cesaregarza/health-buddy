Contract v1 guide · pre-release

Make the workspace yours.

A useful addition includes the source, tests and notes that let someone else maintain it.

Contract examples and implemented guides are separate. This route retains contract fixtures. The pinned source walkthrough now supplies actual scaffolds, testing, preview and recovery commands for the accepted agent guide. It does not advertise a public runtime download.

Ask for a change you can verify

  1. Describe the daily need. Explain what a view, metric, integration or workflow should help you do.
  2. Confirm the interface and authority. The agent discovers your exact release, workspace, supported extension API and allowed sources. Code maintenance requires separate owner authorization; a routine health token does not grant permission to install or enable code.
  3. Build with synthetic examples. Keep the implementation, meaningful tests and a visible preview together. A preview must not create a persistent schedule or production write.
  4. Review and enable. Confirm behavior, scopes, any network destinations and secret references. Native extensions are trusted owner code, not a sandbox for malicious code.
  5. Leave a handoff. Save design decisions and limitations so a fresh Codex or Claude Code session can explain and change the feature.

A metric and its view

“Show my seven-day mean body mass with the number of entries, source and missing-data state. Keep different sources separate.”

The contract example returns 72 kg from 70 and 74 kg, count 2. Its view renders that typed result with coverage and freshness. The metric is deterministic for its explicit inputs, timezone and version; it does not write records or make hidden network requests.

A second agent could add a display-unit option while preserving numerical and missingness tests.

A connector and its workflow

“Normalize a water event from a source I approve, then record it once even if the job is retried.”

The contract event is 250 mL, normalized to 0.25 L. The connector produces validated canonical input; the workflow uses a scoped, revocable write grant and a stable event retry key. Its cursor advances only after a successful receipt. A different payload under that event ID is a conflict.

You explicitly approve the schedule, timezone, source and egress. Merely loading a manifest must not start a job.

Keep the whole personal workspace

Personal extensions are required to live outside replaceable runtime images. Preserve source, assets, non-secret configuration, tests, notes, migrations and authoritative state. Secrets need separate protected storage and explicit references.

A compatible update should preserve that inventory. An incompatible extension must block activation or be explicitly disabled by you while its files and state remain intact. No silent deletion or automatic disabling.

When the request needs core changes

Use a tracked fork tied to an exact upstream commit, with persistent patches, a build recipe and relevant tests. An upstream change requires a deliberate rebase or merge, review and retesting. Arbitrary core edits are not promised automatic compatibility.

Upgrade and clean-host restore qualification must prove that a different agent can maintain both kinds of additions without reconstructing the original chat.

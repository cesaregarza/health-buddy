Contract v1 guide · pre-release

Read your day with context.

Useful records carry their source, time and uncertainty along with the number.

A number needs a source

In the v1 design, each observation identifies its source, observation time, receipt time and unit. Manual and device observations stay distinct. A view uses the canonical operations layer rather than creating another private copy of your health history.

An agent request should specify a bounded date range and the fields it needs. You can review that selected context before sending it to your chosen AI provider.

Synthetic demonstration — planned behavior

Two entries are not a complete week

A weekly body-mass metric receives 70 kg and 74 kg from one synthetic source. It returns 72 kg, count 2, with coverage and provenance. With no observations, it returns no numeric result and an insufficient_data reason. It does not fill gaps with zero or silently merge source series.

Separate freshness from missingness

Fresh, empty resultThe source responded successfully; no matching observations were returned.

Write deliberately, retry safely

Canonical writes are required to check authority, dataset identity and revision. An identical retry returns its original receipt. A changed request using the same retry key or a stale revision surfaces an explicit conflict. Review the latest record and resolve it; a retry is not permission to overwrite.

These are implementation requirements, not proof that every extracted dashboard path already has those guarantees.

A useful routine without an always-on agent

The release target is a dashboard for reviewing and recording daily context on its own. Bring Codex or Claude Code when you want an explanation, a deliberate edit, troubleshooting or a new feature. Missing agents or optional sources should not remove the core workspace.
